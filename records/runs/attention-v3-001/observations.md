# 供課堂反思使用的客觀紀錄

這是對實際紀錄的整理，不是預先編寫的執行故事。僅有本次run，無法判定跨多次執行「哪個節點最常出錯」。

1. 覆蓋率檢查先找出實驗起源、方法、術語與完整書目不足，於人工關卡0停止。使用者授權後補Wiki，重新檢查再做大綱。這避免以模型記憶補研究細節。
2. 兩道隔離審查初次指出來源頁缺完整七筆書目。Wiki已經有資料，但轉成教材時漏載，屬步驟4內容／引用問題。第1輪修正加入書目，再由新隔離上下文重審，兩份均通過。可改善的前置檢查是把「來源頁真的含完整書目」納入稿件完成條件，而不是只看來源ID存在。
3. 使用者批准兩頁樣張後，完整瀏覽器初測有1項失敗，其他586項通過。失敗原因是檢查程式要求高於視窗的整塊封面同時可見，與允許捲動的設計不符。第2輪將目標改為捲到底能看見最後按鈕，沒有改HTML；重跑587項全通過。不能只為了綠燈刪測試，應保留原報告並說明新目標如何對應需求。
4. 排版不只看原始碼：實際跑五組尺寸／字型、截圖、頁底可達、互動與來源返回。部分長頁需要捲動，這是樣張獲准的閱讀方式，不宣稱全部內容都在單一畫面。
5. 管理政策封鎖 `file://`，因此無法在此環境驗證「雙擊離線開檔」。相同位元組在離線瀏覽器測試通過，仍把直接開檔留給人工關卡3補驗。自動化證據與未驗證限制同時保留。

本版相較舊流程，按使用者要求增加樣張關卡及獨立教學品質審查；實際遇到測試誤判後，在Graph補記「測試工具錯誤→修工具→原節點重測」分支。這不是捏造新的學術或畫面缺陷。測試中的遊戲數字是合成作答，不能作為心理學研究發現或真人效應量。

## 後續人工回饋01的實際觀察

人工驗收指出遊戲解讀只重快慢，沒有充分接回原研究與原理。這說明「稿件有提到研究」和「結果回饋能幫助讀者理解研究」是不同檢查項。已返回步驟4補正文9／12，並將動態回饋一併納入凍結稿，交兩個獨立上下文審查；再用合成正向／反向結果檢驗實際呈現。可把「預期方向、比較基準、個人方向及不能指定原因」前移為結果稿的完成條件。

本次也發現守門程式把非阻擋建議當成失敗，另有一次誤啟動舊HTML測試後中止。已保留紀錄、修正守門並新增測試前置核對，再完成617項檢查。這提醒自動化除了教材檢查，也需要驗證「正在測的是否就是目前審過的產物」。仍不能以這一個run斷言哪個節點長期最常出錯。
